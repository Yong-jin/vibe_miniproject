# 박스오피스 변경 검증

## 입력과 기준 찾기

변경 범위, 기대 동작, 사용 가능한 검사 환경을 파악한다. 제공되지 않은 정보는 현재 diff와 실행 명령 정의에서 확인한다. 저장소 루트의 [AGENTS.md](../../../AGENTS.md)와 [PROGRESS.md](../../../PROGRESS.md)에서 현재 단계와 실제 명령 제공 여부를 확인한다.

관련 AC는 [검증 체크리스트](../../../docs/VERIFICATION.md)에서 선택한다. API/캐시 계약은 [상세 구현안](../../../docs/IMPLEMENTATION.md), 테이블·트랜잭션은 [ERD](../../../ERD.md)를 해당 변경에 필요한 만큼 읽는다. 실행 명령은 실제 package.json과 대조한다. 문서에 명령이 있다고 구현된 것으로 가정하지 않는다.

## 변경에 맞춘 검사 선택

| 변경 | 우선 확인 |
| --- | --- |
| 날짜·기간·파싱 | AC01·03·04·05: 달력/KST 경계, 실제 기간, 오류 본문과 정상 빈 리스트 구분 |
| 캐시·폴백 | AC05~09: hit 외부 호출 수, TTL, stale, DB 조회/저장/재조회 실패 분리 |
| DB 구조·저장 함수 | AC09·11·13·14: FK/복합키, 원자적 교체, 롤백, 동시 갱신, 실행 권한 |
| 집계 | AC10: 일별 관측 범위, 누적값 제외, 누락일, 0 이하 분모, 합계의 안전 정수 범위 |

1. 수정 전 예상 실패나 경계 사례를 선택하고 기대값을 적는다. 정상화 함수의 출력 자체를 정답으로 재사용하지 않는다.
2. 가상 fixture와 mock으로 외부 실패를 재현한다. 실제 API 장애를 유발하거나 빈 날짜를 찾기 위해 대량 호출하지 않는다.
3. 관련 명령이 구현되어 있으면 실행한다. 코드 단계의 공통 검사는 AGENTS.md를 따른다. 실패를 수정하는 작업까지 요청된 경우에만 수정하고 관련 검사를 재실행한다.
4. 실제 DB 검증이 필요한 변경은 격리된 환경에서 FK·롤백·동시성·권한을 확인한다. mock 통과로 실제 DB 통과를 대신하지 않는다. live 키·대상이 준비되지 않으면 해당 검사만 미실행으로 기록한다.
5. 원본 대조는 영화 코드 집합·순위·매출·관객·행 수·합계로 판단한다. movies의 최신 관측 이름과 과거 원본 이름의 차이는 별도 정보다. 더 최신 갱신이 선행했다면 같은 버전의 raw_response와 실적끼리 대조한다.
6. 새 원본과 저장본의 차이는 먼저 보고한다. 검증 요청만으로 원격 데이터를 덮어쓰거나 배포하지 않는다.

## 결과와 중단 기준

관련 AC / 데이터 모드(fixture·mock·live API·live DB) / 환경·커밋 / 실제 명령 / 기대값·실제값 / 통과·실패·미실행 / 증거 위치를 보고한다. 기록 형식은 검증 체크리스트를 사용한다. 키와 key 쿼리가 포함된 URL은 증거에서 제거한다.

누락 키·DB 대상 불명·실행 명령 부재는 해당 검사 미실행 사유다. 원본이 불완전하거나 수치가 맞지 않으면 통과를 선언하지 않는다. 수정 범위를 벗어나거나 운영 데이터 변경이 필요하면 독립적인 읽기 검증까지만 마치고 필요한 사항을 보고한다. 이 Skill은 추가 외부 작업 권한을 부여하지 않는다.
