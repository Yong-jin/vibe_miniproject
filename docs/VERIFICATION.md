## 3. 고정 기대값과 테스트 설계

### 날짜·기간

가짜 현재 시각을 2026-09-18T00:00:00+09:00으로 고정하면 기본 일간 날짜는 2026-09-17이다. 자정 직전은 어제 값이 달라지는지 검사한다. 2024-02-29는 유효, 2025-02-29와 2026-02-30은 무효다. 날짜 문자열 형식만 맞는다고 달력 검증을 통과시키지 않는다.

2026-09-08과 2026-09-13의 weekly 키는 모두 2026-09-07이며 실제 기간은 09-07~09-13, weekend는 09-11~09-13이다. 위 현재 시각에서 09-14가 속한 주는 종료 전이므로 거부한다. now==expiresAt은 만료다.

### 집계 — ERD의 가상 예시 사용

| 날짜 | 영화 | 매출 | 관객 |
| --- | --- | --- | --- |
| 2026-09-01 | DEMO_A | 100000 | 10 |
| 2026-09-01 | DEMO_B | 60000 | 6 |
| 2026-09-02 | DEMO_A | 80000 | 8 |

일별 매출 160000/80000, 기간 매출 240000, 관객 24, 원/명 10000, 영화 순위 A 180000 > B 60000이 기대값이다. B의 09-02 부재는 미관측이다. 09-03 빈 날짜를 범위에 포함하면 그래프는 해당 일자 null, 기간 합계와 순위는 숨긴다. 이틀 손계산은 단위 함수 시험이며 화면 필터는 승인된 7/14/30일만 유지한다.

별도 7일 fixture에서는 첫 이틀 위 값, 나머지 5일 A 매출 10000·관객 1씩으로 구성한다. 기대 기간 매출 290000, 관객 29, 원/명 10000, A 230000/B 60000이다. 그중 하루가 실패/empty가 되면 기간 지표를 숨긴다. 누적값을 임의로 크게 바꿔도 해당 기간 집계는 변하지 않아야 한다.

### DB 실패·동시성

검증 전 대상 DB가 격리되어 있는지 확인한다. 부모 FK·중복 검사는 DB에서 직접 거부되는지, 전체 교체·row_count 일치는 저장 함수를 통해 확인한다. 단일 행 CHECK로 자식 개수 일치를 검증했다고 주장하지 않는다.

롤백은 입력 검증 실패만으로 대신하지 않는다. 부모/영화 갱신과 실적 삭제 이후에 실패하도록 격리 DB에서만 테스트용 실패 지점을 구성하여 원래 세 테이블 상태가 유지되는지 확인한다. 제품 저장 함수에 공개 오류 주입 파라미터를 추가하지 않는다. 동시성은 두 DB 연결의 시작·완료 순서를 제어해 검증한다. 테스트 소유 데이터만 정리하고 운영 전체 삭제/reset은 금지한다.

## 4. 결과 기록과 증거

Phase별 docs/verification/phase-NN.md에 다음을 기록한다. 현재 실제 문서 검증 기록은 [Phase 1 결과](verification/phase-01.md)에 둔다.

| 기록 필드 | 내용 |
| --- | --- |
| 대상 | Phase-Step, AC, 변경 범위와 커밋/미커밋 여부 |
| 환경 | fixture/mock/live API/live DB/배포, 시간·Node 버전 등 재현 조건 |
| 실행 | 실제 명령 또는 수동 조작, 테스트 데이터와 기대값 |
| 결과 | 실제 값·종료 코드·통과/실패/미실행; 실패 원인과 수정 후 재검사 |
| 증거 | 로그·캡처 위치; 키·개인 인증값·key URL 제외 |
| 남은 작업 | 검증 불가 사유, 필요한 설정, 다음 검사 |

문서 정적 검사 PASS는 AC 전체 통과가 아니다. DB 권한 검사는 실제 역할로 확인하고 서버 역할 성공만으로 대체하지 않는다. Phase 4의 실제 API 성공은 Phase 5의 캐시 완성을 의미하지 않는다. 키나 DB가 없으면 관련 live 항목은 미실행으로 남긴다.
